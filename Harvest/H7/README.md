# Harvest H7: declaration syntax leaves, proved against Lean 4.34.1

Built here with a local Lean 4.34.1 (`lean -o` per file; `Review.lean` prints axioms): every theorem uses only `propext`, `Classical.choice`, `Quot.sound` (or none). No sorry/native_decide. Files: `DefView.lean`, `Modifiers.lean`, `Review.lean` (proofs), `Tokens.lean` (guards only). Lake: `[[lean_lib]] Harvest` added to `lakefile.toml` on this branch only. Lean source: `src/lean/` of the 4.34.1 release tarball.

**Finding that shapes the harvest.** Lean's parsers are `leading_parser` closures; their `ParserInfo` (first tokens, token list) is total data, but every `symbol "x"` stores `"x".trimAscii.copy` (Parser/Basic.lean:1114) and `String.trimAscii` is not kernel-reducible in 4.34.1 (`"ab ".trimAscii.copy = "ab"` by `decide`/`rfl` gets stuck). So `decide +kernel` on any `Parser.info` fails; those tables are guards (`#guard`, compiled evaluation), not proofs. The pure `Syntax -> DefView` functions in the elaborator are fully provable (for ALL syntax trees).
