# mixHash port (branch `mixhash-port`)

Lean core `mixHash` (`@[extern "lean_uint64_mix_hash"] opaque`, `Init/Prelude.lean`) has its C code in
`lean.h:1952` (Lean 4.29.0). The code was checked against the prompt's description; it matches.

## What was done

- `Riscv/Frontx/MixHash.lean`
  - `MixHashPort.mixHashLean`: the C code, line for line (`k*m`, `k ^= k>>47`, `k ^= m`, `h ^= k`, `h*m`).
  - `Proven.WA.MixHash.fuzzRun`: `#eval fuzzRun 1000000` compares it with native `mixHash`. Throws on any mismatch.
  - `mixHashE : ByteArray → UInt64`: glue (words at bytes 0 and 8), then `wa_compile mixHashE`.
- `Testing/asm/emit_wa.lean`: one import and one emit entry (`emitIn "mixhash" …`, 65 cases).
- `Testing/asm/frontx-words/wa_mixhash.{words,cases}`: generated, committed.

## Fuzz (native `mixHash` vs `mixHashLean`)

- Tested: 1,000,025 pairs = 25 edge pairs (0, 1, 2^63, 2^64-1, m, all pairs) + 1,000,000 xorshift64 pairs.
- Mismatches: **0**.

## Theorem

- `Proven.WA.MixHash.mixHashE.implements1` (generated by `wa_compile`), with `Proven.WA.MixHash.mixHashE.good`.
- Source-level `.good`: depends on `propext`, `Quot.sound` only.
- `.implements1`: depends on the same axiom set as every machine theorem in the repo (the Sail model axioms,
  `riscv_*`, `plat_term_write`, … plus `propext`, `Classical.choice`, `Quot.sound`; identical to `Ops.ops64E.implements1`).
  These axioms cannot be removed: they come from the RISC-V model. Nothing else is added.
- No `sorry`, no `native_decide` (`Lean.ofReduceBool` does not appear). The generated proofs use `decide +kernel`, as the other `wa_*` theorems do.
