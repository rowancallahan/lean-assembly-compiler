# lean-assembly-compiler

Machine code proved correct against Sail-generated CPU models in Lean 4. Work in progress.

## What is kernel-checked today (RISC-V, Sail model `opencompl/sail-riscv-lean`, unmodified)

Source language (`Proven/Code.lean`): `Exp` over four 64-bit inputs (`a0..a3`), 64-bit constants, and
- `bin op a b` with `op` one of `add sub and or xor` and
  - `shl / lshr / ashr`: shift by `b.toNat % 64` (`a <<< (b.toNat % 64)`, `a >>> ..`, `a.sshiftRight ..`),
  - `ult / slt`: `if a < b then 1 else 0` (unsigned) / `if a.slt b then 1 else 0` (signed),
  - `eq`: `if a = b then 1 else 0`;
- `ite c a b`: `if c = 0 then b else a` (branch-free: both arms are evaluated).

RV64I code (base ISA only): R-type `add sub and or xor sll srl sra slt sltu`, `sltiu t,t,1` (for `eq`),
`sltu t,x0,t; sub t,x0,t` + `xor/and/xor` mask arithmetic (for `ite`), over 11 temporaries `t0..t6, a4..a7`.

- `Proven.compile_ok` (`Proven/Compiler.lean`): for every `e : Exp` with `e.depth < 11`, the code `compile e`
  placed anywhere in RAM runs on the Sail model with no trap and no model error, returns to `ra`, leaves
  `a0 = e.denote (a0, a1, a2, a3)`, leaves memory unchanged, keeps callee-saved registers and the control state `Cfg`.
  (`depth` counts the extra temporaries needed: `bin`: `max a.depth (b.depth + 1)`, `ite`:
  `max c.depth (max (a.depth + 1) (b.depth + 2))`; there is no spilling, so deeper expressions are rejected.)
- Per-instruction step lemmas for every emitted word: `Proven/Words.lean`, generated by `Proven/gen_words.py`
  (one `step_word` proof per concrete word, ~215 lemmas, ~6 min to build).
- `Proven.demo_ok`, `Proven.demo2_ok` (`Proven/Reify.lean`): the same for Lean functions `demo` / `demo2`,
  reified by `reify%` (which accepts `+ - &&& ||| ^^^`, the shift forms above, `if a < b then 1 else 0`,
  `if a.slt b then 1 else 0`, `if a = b then 1 else 0`, `if c = 0 then y else x`, and closed constants);
  `demo2` uses every new operator.
- Axioms used (from `#print axioms compile_ok`): `propext`, `Classical.choice`, `Quot.sound`, plus axioms declared by
  the generated model: `cancel_reservation`, `get_16_random_bits`, `load_reservation`, `match_reservation`,
  `plat_term_write`, `sys_enable_experimental_extensions`, `valid_reservation`, and the 67 softfloat externs
  `riscv_f16Add` ... `riscv_ui64ToF64` from `LeanRV64D/RiscvExtras.lean` (they enter through `try_step` in
  `Proven/Step.lean`, already before the operators above were added; no float instruction is executed). No `sorryAx`.

### Loops (RISC-V; `Proven/Branch*.lean`, `Proven/Loop*.lean`)

- Branch/jump step lemmas with a **symbolic** offset (`Proven/Branch.lean`, generated `Proven/BranchWords.lean` by
  `Proven/gen_branch.py`): `b<op> rs1, rs2, 2*o` for `op ∈ beq bne blt bge bltu bgeu`, `rs1 ∈ {t0,t1,a0..a3}`,
  `rs2 ∈ {x0,t0,t1}` (84 instances; `bltu/bgeu` with `x0` omitted), any `o : BitVec 12`, and `jal x0, 2*o` for any
  `o : BitVec 20`. Each: one retired step, `PC = if bcond op x[rs1] x[rs2] then pc + signExtend(o++0) else pc + 4`
  (`step_<op>_<rs1>_<rs2>`, `step_jal_0`), registers and memory unchanged (`jal` writes `rd = x0`), `Cfg` kept.
  The model has C (`misa` bit 2) enabled, so `jump_to` only requires target bit 0 = 0 (2-alignment); our offsets
  are multiples of 4 (`boff_fwd`, `joff_back`). The decoder is run on `c ||| imm o` with bit-range lemmas
  (`B_known`/`B_mismatch`/`B_imm`); all bit-level side lemmas are proved by kernel-checked bit enumeration
  (`bits`), not `bv_decide`.
- `runsTo` rules (`Proven/LoopRule.lean`): `runsTo_mono`, `runsTo_trans`, and the loop rule `runsTo_loop`
  (invariant + `Nat` measure; `runsTo_while` with explicit head/exit PCs).
- `Proven.compileS_ok` (`Proven/Loop.lean`): source `Stmt` = `assign (v : Fin 4) (e : Exp) | seq | loop c body`
  (`while c ≠ 0`), variables `a0..a3` (`gen` never uses them as temporaries), big-step semantics `Exec`
  (`Exec.loop_of`: loops via a user-supplied measure). If `Exec p σ σ'` and `p.wf` (expression depth < 11, each loop
  fits the `beq` range), the code `compileS p` (expressions by `gen`, `beq t0,x0` exit, `jal x0` back edge) placed
  anywhere in RAM runs to its end with `a0..a3 = σ'`, memory unchanged, callee-saved registers and `Cfg` kept.
  `compileF_ok`: same for `compileF p = compileS p ++ [ret]`, returning to `ra`.
- `Proven.sum_ok`, `Proven.gcd_ok` (`Proven/LoopExamples.lean`): the ordinary Lean functions
  `sumDown n acc = if n = 0 then acc else sumDown (n-1) (acc+n)` and
  `gcdSub a b = if a = 0 then b else if b = 0 then a else if a < b then gcdSub a (b-a) else gcdSub (a-b) b`
  (well-founded recursion), `Stmt` programs `sumProg`, `gcdProg`, proofs `sumProg_exec`/`gcdProg_exec` that they
  compute them (`Exec.det`: the result is unique), and the machine theorems (`a0 := f a0 a1`, return to `ra`).
- Axioms: the same list as `compile_ok` above (no `sorryAx`, no `bv_decide`/`native_decide` axioms).
- Check times: `BranchWords` ~7 min (one `bstep` per lemma, ~1.6 s), `Branch` 7 s, `Loop` 7.5 s,
  `LoopExamples` 1.2 s, `LoopRule` 0.7 s. Build with `lake build Proven.LoopExamples`.

## Tested only

- `Proven/CompilerArm.lean`: AArch64 backend for the same `Exp` (`lslv/lsrv/asrv`, `cmp` + `cset lo/lt/eq`,
  `cmp #0` + `csel ne`, temporaries `x9..x15, x4..x7`). Not proved.
- `asm/triple.py asm/ctest/triple.txt` (input from `asm/triple-data/triple.lean`): for 18 expressions (every
  operator, edge inputs 0, 1, 2^63, 2^64-1, shift amounts 0, 63, 64, 65, 127, 128, 2^64-1, nested `ite`, a depth-10
  expression using all 11 temporaries) and 17099 inputs in total: Lean `Exp.denote` == RV64 code on QEMU ==
  RV64 code on the Sail C emulator == AArch64 code on QEMU.

- `asm/loop_test.py` (words from `asm/emit_loops.lean` in `asm/loop-words/`): `compileF sumProg` and
  `compileF gcdProg`, 300 inputs each (sum: n < 400, any acc; gcd: small values, big multiples of a big gcd,
  consecutive Fibonacci numbers up to 2^64, zeros, a = b), QEMU == Sail C emulator == Python model.

## Not proved

- `Proven.sort_ok` (`Proven/Sort.lean`): stated with `sorry`.
- `Proven/SortSteps.lean`: per-instruction lemmas for the sort; 5 of them currently fail with
  `(kernel) deep recursion detected`.
- Nothing is proved against the ARM model yet.

## Layout

- `Proven/Spec.lean` — the specification (`Cfg`, `Retires`, `runsTo`, `Implements`, ...). Read this first.
- `Proven/SailEval.lean` — `sail_eval`, a call-by-value symbolic executor tactic for Sail models.
- `Proven/Regs.lean`, `Proven/Step.lean` — register facts and per-instruction step lemmas for `try_step`.
- `Proven/Code.lean` — source language `Exp` and the RV64I code generator.
- `Proven/Words.lean` (generated by `Proven/gen_words.py`), `Proven/Compiler.lean`, `Proven/Reify.lean` — step
  lemmas for the emitted words, the compiler proof, and `reify%`.
- `Proven/CompilerArm.lean` — AArch64 code generator (tested, not proved).
- `asm/` — RV64I merge sort, QEMU vs Sail C emulator co-simulation (`cosim.py`), compiler test.
- `asm-arm/` — AArch64 merge sort and QEMU harness.
- `arm-gen/` — `regen.sh` regenerates the ARM Lean model from pinned upstream commits; `DIFFS.md` lists every
  diff from upstream.
- `armv9-lean/` — generated ARM v9.4-A Lean model (do not edit by hand).
