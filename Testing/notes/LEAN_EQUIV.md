## Result
T and done: rows 1, 2, 4, 5, 11 (adjacent function), 12, 14, 15, 17 (17 theorems; axioms `propext`, `Quot.sound`, and `Classical.choice` in `numeral_sub_toNat?` via Std's lemmas; `Nano/LeanEquiv/REVIEW.lean`).
Target form (owner, 2026-11-21): SUBSET: nano accepts ⇒ Lean's function accepts with the same value. Equalities are kept where they fall out.
Finding restated as a theorem: row 2: nano's identifier-first set = Lean's ∪ {`'`}. Removing 39 there makes it an equality.
Everything about *sequencing* (token loop, comments, Pratt loop, layout) is `partial` in Lean: no kernel theorem is possible against Lean's code; only against a hand-written total mirror, whose faithfulness is again a fuzz claim.

## Where the proof stops
Per construct: **proved** = kernel theorem against a Lean 4.34.1 definition (name in `Nano/LeanEquiv/`); **fuzzed** = Lean's code is `partial`/stateful, only differential testing (LEAN-DIFF, LEAN_RULES batteries); **rejected** = meaning is the elaborator's, nano must refuse what it cannot match (open items keep their M-number).

| construct | proved (leaf) | fuzzed only (combination) | elaborator meaning → conservative rejection |
|---|---|---|---|
| identifier | every byte after the first is a Lean `isIdRest` char (`isW_imp_isIdRest`); first byte is a Lean `isIdFirst` char unless it is `'` (`idFirst_imp_isIdFirst`, `idFirst_eq_lean`) | that Lean's `identFnAux` builds the same name from those chars; that the word is not a Lean token (reserved words, M6); `'x` (M7, **open, nano accepts**) | name resolution, root-name clashes (M8), namespaces (M4, M5) |
| numeral | digits are Lean digits (`isD_imp_isDigit`); a digit word is read by `String.toNat?` with value `decVal` (`numeral_sub_toNat?`); the stored `UInt64` is Lean's `UInt64` literal of that value (`numVal_eq`, `numVal_eq_lean`) | that Lean's tokenizer ends the numeral where nano does (`takeDigitsFn`, `numberFnAux`) and that `decodeNatLitVal?` = `String.toNat?` on digit words | the literal's type: Lean defaults to `Nat` (M1, M2 open) |
| whitespace | skipped bytes are `Char.isWhitespace` (`ws_imp_lean`); Lean's set is exactly space, LF, tab, CR (`ws_eq_lean`) | Lean's `whitespace` loop | — |
| comments | nothing | all of it: `finishCommentBlock` nesting, `--` to end of line, doc-comment tokens, `<--` (M3 open) | doc comment / `@[…]` / `private` position (M13, M14) |
| operator tokens | spelling of the 7 binary operators, `==`, `<`, `×` = Lean's notation symbols (`binOps_eq_lean`, `cmp_prod_lean`) | longest match over Lean's whole token table (`Trie.matchPrefix`) | — |
| binary expressions | precedence numbers and left associativity equal Lean's declarations, no operator missing (`binOps_eq_lean`, `binOps_complete`) | that Lean's Pratt loop (`trailingLoop`) and nano's `pLoop` build the same tree from equal tables; shift rhs restriction | operand typing, unification order (M12) |
| `if … then … else` | Lean's syntax is the three keywords around three `term:0` slots; keywords are nano's tags (`ite_lean`); comparison operators at 50 with operands at 51 (`cmp_prod_lean`) | that nano's `pExpr` condition form `A (==\|<) B` is parsed the same by Lean's term parser | `Decidable` instance choice, `Bool` vs `Prop` condition |
| operator meaning | each operator tag evaluates to the Lean function its notation names, on `UInt64` (`binop_eq_lean`, `binFns_eq_lean`) | that Lean's macro for the symbol yields that function (`macro_rules` code) | instance choice (`UInt64` vs `Nat`: M1) |
| `let`, tuples, parens, application | nothing (Lean: `leading_parser` closures) | all | layout columns (M10) |
| `match` | nothing | desugaring `DsSpec.ds` vs Lean's `match` | arm layout (M9), redundancy (M11) |
| `def`, binders, types | `×` precedence/right assoc (`cmp_prod_lean`) | header and binder grammar | modifiers, attributes (M13) |
| reserved words | nothing | list extracted from a running Lean (LEAN_RULES §3) | M6 open |

Reading the table: the left column is closed for good (it changes only with the Lean version: re-run `REVIEW.lean`). The middle column is where Lean has no total definition, so the boundary cannot move without a hand-written mirror of Lean's loop. The right column is not a parsing question.

## Proposed spec mirroring (needs SYNTAX-EXP; not done)
* `LexSpec.isW := fun b => Lean.isIdRestAscii b && b != 33 && b != 63` and `isD := fun b => (Char.ofNat b.toNat).isDigit` would make rows 1, 4 definitional. Cost: every `decide` over `isW` in Lex2Sound re-checks; no gain in trust over the theorems here. Recommendation: keep nano's definitions, keep the theorems.
* Row 2: reject a word starting with byte 39 in `step` (changes the trusted spec and the lexer `s10`; selfhost_gate needed).
