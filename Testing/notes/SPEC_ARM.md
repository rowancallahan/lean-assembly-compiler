# ARM machines in `Spec/` — design note (SPEC-ARM, 2026-11-20; step 1, no Spec/ edits yet)

Goal (ROADMAP "ARM in the spec"): `C_correct_armSail` (and `C_correct_armDM`) stated against machines whose text is
in `Spec/` and frozen, as `riscv` is. Today `armSail` is in `Arm/sail/ArmSail/Machine.lean`, `armDM` in
`Arm/apc/Blocks/ArmDM.lean`, and `CompileCorrectP` / `ArmLoader` (used by the DM statement) in
`Nano/Main/TopOn.lean` / `Proof/Machine/A64Sem.lean`.

What a Spec/ `armSail` must contain (same meaning as today): `stepModel` (3 lines), `xget` (+ `xreg`, `xreg_ty`),
`ArmFullB` and the 30-field `Pins` (generated by `Arm/gen/pins.py`, with `featV`, `edscrV`), `obsS`, the RAM window.
About 90 lines. `armDM`: `Pg`, `abs`, `stepDM`, `obsDM`, `XD`, `WD` — about 40 lines. Model-independent:
`CompileCorrectP`, `CompileRunsP`, `ArmLoader`, `InBlocks` (if not already in Spec) — about 30 lines.

Complication: the root lake project (root `Spec` lib, glob `Spec.+`) does not have the Sail ARM model (out-of-repo
partitioned build `../../../armv9-lean`) nor DeepMind's (`../../../deps/code-verification`). Both sub-projects already
compile `Spec` from `../..` as their own `Spec` lib.

## Option A — model-dependent Spec files built only by the ARM sub-projects (RECOMMENDED)
- New: `Spec/ARM/Sail.lean` (armSail), `Spec/ARM/DeepMind.lean` (armDM, XD, WD), `Spec/Loader.lean`
  (CompileCorrectP/RunsP, ArmLoader; model-independent, built by root). Spec/README gets 2 lines saying which project
  builds `Spec/ARM/*`.
- Root `lakefile.toml`: Spec lib excludes `Spec.ARM.*` (explicit module list or a non-recursive glob).
  `Arm/sail` / `Arm/apc` lakefiles: their `Spec` lib adds `Spec.ARM.Sail` / `Spec.ARM.DeepMind` + `Spec.Loader`.
- Proof side: keep the existing defs; one bridge per machine, `Spec.armSail = ArmSail.armSail := rfl` (kernel
  checks the copies agree, so the duplicated `Pins` text cannot drift silently), and `CompileCorrectP` (Spec) =
  `NanoMain.CompileCorrectP` by `rfl`. Top theorems restated as `CompileCorrect Proven.Top.armSail …` and
  `CompileCorrectP Proven.Top.armDM (Proven.Top.ArmLoader XD WD) …`. No edits to Gen/Machine/Main (CLEANUP's files).
- Owner reviews: ~160 new Spec lines (3 files) + 2 README lines; FROZEN.sha256 then lists 14 files.
- Build cost: none new. Root build unchanged; ARM projects add 3 small modules.
- Trust: ARM statements become Spec-reviewed and frozen like RISC-V. Caveat: `Spec/ARM/*` is never compiled by the
  root build, only by the ARM projects (spec_check still hashes it); `Pins` is a generated list copied into Spec
  (re-copy if pins.py changes; the rfl bridge fails loudly otherwise).

## Option B — make both ARM models root dependencies
- Files: as A, but no exclusion; root `lakefile.toml` gains `require armv9` and `require arm64` (paths outside the
  repo); ARM sub-project Spec libs can be dropped later.
- Owner reviews: same Spec text, plus the root lakefile.
- Build cost: every root `lake build` needs the partitioned Sail ARM build (out-of-repo, long first build) and the
  DeepMind clone; root breaks wherever they are absent (they are absent in fresh containers, as in this one).
- Trust: same as A, and Spec is compiled in one place. Not worth the cost.

## Option C — abstract ARM machine in Spec, instantiated outside
- Spec defines `armSailOf (M : SailArmModel)` over an abstract step/regs/mem interface; `Arm/sail` instantiates it
  and proves the instance equals `armSail`.
- Owner reviews: a smaller, model-free Spec file — but the meaning lives in the instantiation (which registers,
  which pins, which step), which stays outside Spec. The gap is not closed. Not recommended.

## Recommendation
A. Step 2 order: Spec/Loader.lean + Spec/ARM/{Sail,DeepMind}.lean, lakefile edits, bridges + restated tops, checks,
then FROZEN.sha256 last ("pending owner approval"; no `--freeze` run).
Risk: `../armv9-lean` and `../deps/code-verification` are not present in this container; building Arm/sail and
Arm/apc needs them regenerated/cloned first (Arm/gen/build_part.sh, Arm/apc/check.sh), which may hit network or time
limits — reported if so.
