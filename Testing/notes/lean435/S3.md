Root causes, as far as diagnosed:
- `simp`/`simpa` no longer turns `(a :: l)[i+1]` into `l[i]`. Reproduced in a standalone example (`simpa using hr (i + 1) (by simpa using hi)` against a goal about `l[i]`). Hits ParInvValRep, probably more of the simp group.
- `rw [if_pos h]` says "pattern not found" on a goal that prints exactly that pattern (ParRunFlat, ParInvArg). Not reproduced standalone, not diagnosed. Probably a Decidable-instance difference after `simp only [stepF, …]`.
- Default `decreasing_by` in a mutual recursion on `sizeOf` (ParTreeOK).
- The remaining failures were not diagnosed individually; first error lines are in the table.

Not errors: about 1200 deprecation warnings (`if_true`→`ite_true` 412, `if_false`→`ite_false` 394, `if_pos`→`ite_eq_left` 204, `if_neg`→`ite_eq_right` 200, `dif_pos`→`dite_eq_left` 12). The old names still resolve on 4.35.0.

## Method and limits

- Each module was compiled with `lean -o` directly, not lake (the lakefile requires the Sail dependency, which is absent here). Flags as in the lakefile: `--tstack=400000 --threads=2`.
- To reach modules downstream of a failure, each failing declaration had its proof replaced by `sorry` in the scratch copy, statement kept, and the build went on. So every module was elaborated, and errors downstream of a sorried theorem are not cascades.
- Inside one failing declaration only the errors Lean reported in that pass are counted. Fixing the first may expose more.
- No 4.29.0 baseline was run. The failures are assumed to be new in 4.35 because the branch is said to build on 4.29.0.
- ParInvRun has no timing (lost by the survey driver); its errors are from its log.
