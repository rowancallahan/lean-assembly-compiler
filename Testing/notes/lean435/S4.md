# SURVEY-S4: Lean 4.35.0, compiler C Sail-free proof folders

Scope: `Nano/V2Self/Proof/{Own,Cert,SrcLink,Bridge,Gen}` (201 modules), source at `ab0e3c5f` (branch `nano-v2-src`),
Lean 4.35.0 (commit eb6cafb7), no source or toolchain changes. 4 cores, 15 GB.

Method: no lake, no Sail checkout. A script computes the import closure, marks every module that transitively
imports `LeanRV64D` as "needs Sail model", and compiles the rest in dependency order with
`lean --tstack=400000 --threads=2 -o` (3 jobs in parallel). Nothing was sampled: every Sail-free module was built.
When a module fails, its `.olean` is still produced by a small error-tolerant frontend wrapper (failed proofs
become `sorry`), so downstream modules are checked too. "upstream errors? yes" = the module was checked on top of
such an olean; its own errors are still real. Wall times of *errored* modules include that second run (roughly 2x).

## Error categories in the unit (35 errors)

1. **Kernel deep recursion, 28 errors, 17 files** (Own P4 P9 P11-P22 P25 P29, Cert.OutSpec). Category: other.
   `(kernel) deep recursion detected, use set_option maxRecDepth` reported at the theorem name, i.e. elaboration
   succeeds and the kernel rejects the term. Typical shape: `reach_one`/`rw [stp_eq, ...]`/`unfold oNN`/`simp only [lit]`
   step lemmas over big `if` trees. Not a stack problem: `--tstack=4000000`, `ulimit -s unlimited` and
   `-DElab.async=false` change nothing. Probes with a file-wide `-DmaxRecDepth`:
   - OwnP9: 4000 fixes both errors, file fully OK in < 100 s.
   - OwnP11/12/13: 1024 not enough (same errors); 4000 file-wide ran > 300 s at 2.8 GB without finishing
     (killed), so a blanket raise is not usable; needs a scoped `set_option maxRecDepth N in` per theorem,
     or the proofs need restructuring so the kernel term is shallower.
   - OwnP11/13 at 2000: still the same error after 20 s. Cert.OutSpec at 4000: > 3 min without finishing
     (4 s at the default), killed. So the passing window between "too low" and "very slow" is unknown for most files;
     only OwnP9 is confirmed fixable by the option alone.
2. **simp result changed, 4 errors** (OwnP3 L200, OwnP21, OwnP26 x2). `simpa using h` / `simp` now leaves a different
   normal form (e.g. OwnP3: `A.F.set (e/4-1) true` no longer rewritten away). Category: simp lemma changed.
3. **rw / if-lemma behaviour, 3 errors** (OwnP8 x2 "motive is not type correct" on `rw [r0, show A.i = A.i + 0 ...]`;
   OwnP14 x1 "did not find pattern"). Same family as the upstream `rw [if_pos h]` failures: `if_pos` is now a
   deprecated alias of `ite_eq_left`-style lemma and no longer matches. Category: deprecated name / simp lemma changed.

No omega/decide, universe or timeout failures inside the unit.

## Effort estimate (prover-hours)

- Category 1: 28 theorems. If scoped `maxRecDepth` works per theorem: 2-3 h (mechanical, but each probe costs
  minutes of build). If some need restructuring (likely for P11-P13 given the 4000 probe): add 4-8 h. Estimate 4-10 h.
- Categories 2+3: 7 errors, local fixes, ~15-20 min each: 2 h. More may surface once upstream sorries are gone
  (unlikely to be many: Own statements do not change).
- Unit total: **6-12 prover-hours**, dominated by the kernel-recursion risk.
- Not in this unit but blocking it: Parser/Machine/Compiler.Opt.Flow, 84 errors in 26 files
  (ParRunWFStep 29, ParInvRun 21 are cascades from 1-2 root causes each): roughly 8-15 h, owned by other units.
- Sail-dependent 101 modules (all of Bridge, nearly all of Cert/Gen): not assessed here.
