# SURVEY-S5 — Lean 4.35.0: compiler #1 Sail-free modules (Nano/ outside Nano/V2Self, Compiler/)

Source: `nano-v2-src` @ `ab0e3c5f`. Toolchain: Lean 4.35.0 (release tarball, commit eb6cafb7), x86_64 Linux, 4 cores / 15 GB.
No toolchain or proof change committed; built in a scratch copy.

## Method

- No `lake` (the `Lean_RV64D` path dependency `../deps/sail-riscv-lean` is absent). Each module was compiled directly with
  `lean --tstack=400000 --threads=2 -o M.olean M.lean` (the lakefile's `moreLeanArgs`), in import order, 3 jobs in parallel, under `/usr/bin/time -v`.
- "Needs Sail model" = imports `LeanRV64D` or a `Spec.Riscv*` module, directly or transitively (computed from the `import` lines). Not built.
- 9 Sail-free modules outside the unit are imported by it and were built as dependencies: Riscv.Direct.SortMergeList, Riscv.Steps.Imm12, Riscv.Steps.SailEval, Spec.Alloc, Spec.ArrCode, Spec.Code, Spec.Encode, Spec.Machines, Spec.Top (all OK).
- When a module failed, an olean was still written from the error-recovered environment (failed proofs become `sorry`) by a small `lean --run` driver,
  so that its dependents were surveyed rather than reported as blocked. Wall times below are the plain `lean` run only.
- **Error counts are lower bounds**: the first failing tactic in a proof hides any later failure in the same proof.

elaboration/universe errors, or timeouts. Root cause was **not** isolated: minimal standalone repros of the generic steps
(`simpa using h` with `h : decide (x = 0#64) = false`; `rw [if_neg …]` on a Nat `if`) pass on 4.35.0, so the failures depend on how the
project's own definitions unfold under `simp [...]` (e.g. `Cond.eval`, `stubEnv`/`BEnv.set`). A Decidable-instance / unfolding-transparency change is my guess, untested.

## Effort estimate

- 54 visible failing sites in 24 modules, all local `simp`/`simpa`/`rw` repairs (add or drop a simp lemma, replace `simpa using` by an explicit `exact`/`rw`, delete a now-redundant trailing tactic). Allow 1.5–2x for sites hidden behind the first failure in a proof: roughly 80–110 sites.
- At 8–12 min per site including rebuilds (the slowest affected file compiles in 18 s): **about 12–20 prover-hours**. Finding the common root cause first could cut this substantially, since the `decide (… = 0#64)` and `if_pos`/`if_neg` patterns repeat.
- Optional: clearing the 958 deprecation warnings is a mechanical rename (`if_pos`→`ite_eq_left`-style), about 1 hour, but check that the replacement names take the same arguments.
- Not covered: the 71 Sail-dependent modules (need the Sail model built on 4.35.0 first); they will inherit breakage from the 24 failing modules they import and may add their own.
