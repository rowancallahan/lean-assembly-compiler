# SURVEY-S7: Lean 4.36.0, Sail RISC-V model + Spec/Compiler

Survey only; nothing in the repo was changed. All builds in scratch copies. Box: 4 cores, 15 GB.
Toolchain: `lean-4.36.0-linux.tar.zst` from the GitHub release (commit 611c117b).
Repo at nano-v2-src HEAD; model = `../deps/sail-riscv-lean` from `origin/build-cache` (opencompl/sail-riscv-lean @51c635c, built for 4.29.0).

## Verdict

**BLOCKED at the Sail model.** `LeanRV64D.Defs` does not compile on 4.36.0 and no source-level patch was found; it needs regeneration with a changed Sail Lean backend (or a Lean fix). Everything that imports the model (17 of 112 Spec/Compiler modules, and all of `Riscv.*`) is therefore untested.

The 95 Spec/Compiler modules that do not import the model all build on 4.36.0 after mechanical fixes (below).

First error:

```
LeanRV64D/Defs.lean:751:0: tag for constructor 'LeanRV64D.instruction.VIMCTYPE' is too big, this is a limitation of the current runtime
LeanRV64D/Defs.lean:751:0: `LeanRV64D.instruction` was not compiled; `compileDecls` must run on inductive types first
... failed to compile definition, consider marking it as 'noncomputable' because it depends on 'instruction.ctorElim', which is 'noncomputable'   (x97, then maxErrors)
```

Cause: `inductive instruction` has 353 constructors, all with a field. On 4.36.0 an inductive may have at most 244 constructors that carry fields. Minimal repro (no imports): an inductive with 244 `| cN (_ : Nat)` constructors compiles, 245 fails with the same message. `instruction` is the only inductive in the model above 200 such constructors.

Tried, none works: `noncomputable section` around it; `noncomputable inductive` (rejected: "Inductive declarations cannot be marked as noncomputable"); dropping `deriving`; `compiler.enableNew` (option no longer exists).

Not checked: in which release between 4.29 and 4.36 the limit appeared (other units' versions will show it); whether the rest of the model has further errors.

Upstream opencompl/sail-riscv-lean `main` still pins 4.29.0, so there is no regenerated model to pick up.

Ways out, none attempted:
1. Change Sail's Lean backend to split `instruction` (e.g. nested sum of sub-inductives, each <= 244) and regenerate. Changes every `instruction.X` pattern in the model and in this repo's `Spec.Riscv*` / `Riscv.*` proofs.
2. Hand-patch the generated `Defs.lean` the same way. Same downstream cost, and it diverges from the generator.
3. Stay on a Lean version before the limit.

### The two causes

1. **`simpa ... using h` now closes at reducible transparency.** (`Lean/Elab/Tactic/Simpa.lean`: `useReducible := true` for `using`, `false` for the new `using!`.) Proofs that relied on the final match unfolding a definition (`Arg.eval g (.i 0)` vs `.w 0`, `RvK Kd.t` vs `Rv`, `(C.fa ..).W` vs `C.W`, `T.len` vs `(T.words _).length`) fail with "Type mismatch: After simplification". `using!` restores the old check. Spec + Compiler have 337 `simpa ... using` lines; the blanket sed fixed all of this class.
2. **Instance arguments are no longer unified at default transparency** (`backward.isDefEq.respectTransparency`, default true). After `simp [Cond.eval, Arg.eval]` the proposition inside `decide` is simplified but the `Decidable` instance still mentions the unsimplified terms (`instDecidableEqBitVec (Arg.eval ...) (Arg.eval ...)`), so `decide_eq_true_eq`, `if_neg` etc. no longer match. Reproduced in a 5-line file against `Compiler.Opt.IR`. Sites: `Flow` 266, 373, 494, 516, 525; `MemCode` 1852; `S3.LowerOk` 58. Setting the option to false fixes all 7 and makes one `rfl` in `Opt/Sel.lean:425` redundant ("No goals").

No omega/decide, universe, or heartbeat failures were seen in these 95 modules.

Warnings on 4.36.0 (not errors): about 350 deprecations (`if_neg` 144, `if_pos` 115, `if_true` 46, `if_false` 38, `dif_pos` 8; replacements `ite_eq_right` / `ite_eq_left` / `ite_true` / `ite_false`), 86 "This simp argument is unused".
