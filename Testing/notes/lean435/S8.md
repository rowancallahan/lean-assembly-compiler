# SURVEY-S8: Sail-free parts of `Riscv/` on Lean 4.35.0

Toolchain: `lean-4.35.0-linux` (commit eb6cafb7), from the GitHub release asset.
Source: `nano-v2-src` at the commit this note is added to. Scratch copy only; nothing but this file changed.
Each file was compiled alone with `lean --tstack=400000 --threads=2` (the lakefile's args); none of the
Sail-free modules import each other or anything outside core `Lean`.

## Headline

Only **5 of 200** `Riscv/` modules are Sail-free. The other 195 reach `LeanRV64D` transitively
(through `Spec.Riscv`, `Spec.RiscvMachine` or `Spec.Implements1`), and `../deps/sail-riscv-lean`
is not present in this container, so they were not built. This unit therefore says almost nothing
about how the bulk of `Riscv/` (about 54k lines) behaves on 4.35.0.

Sail-free was decided by transitive import closure over `Riscv/`, `Spec/`, `Compiler/`
(any path to a `LeanRV64D*` import counts as Sail).

### The one error

`Riscv/Steps/MemDebug.lean:12:35: error: Application type mismatch: The argument decl has type Declaration but is expected to have type USize in the application @Environment.addDeclCore __do_lift 0 decl`

`Lean.Environment.addDeclCore` gained a `maxRecDepth : USize` argument after `maxHeartbeats`.
Fix checked in the scratch copy: `addDeclCore 0 decl none` -> `addDeclCore 0 0 decl none`; the file
then compiles (one unused-variable linter warning, `xs` at line 27). `MemDebug` is a debugging
tactic (`kfind`); no other module imports it.

### Deprecations

`if_pos` -> `ite_eq_left`, `if_neg` -> `ite_eq_right` (warnings only on 4.35.0). Three hits in the
built files. Static count in the unbuilt part (word matches, not verified by a build):

| Steps | 19 | 4201 | 17 | 11 | 97 | 106 | 1615 |
| Direct | 18 | 3962 | 69 | 2 | 576 | 169 | 577 |
| Back | 30 | 6408 | 44 | 4 | 516 | 256 | 573 |

So expect about 470 deprecation warnings in the default targets; mechanical rename, but only worth
doing once the toolchain is actually bumped (the new names may not exist on 4.29.0; not checked).

Meta-programming exposure (files that `open Lean` / use `Lean.Elab` / `Lean.Meta`, the same kind of
breakage as MemDebug) is concentrated in `Riscv/Steps/Gen*.lean`, `Steps/Step.lean`, `Steps/Regs.lean`
and several `Riscv/Back/*` files. Those are the first place to look when the Sail model is available.

## Effort estimate

- Sail-free part: **under 0.1 prover-hours**. One one-token fix (MemDebug), three optional renames.
- Sail-dependent part (195 modules): **no measurement, so no number from this unit**. It is gated
  first on `sail-riscv-lean` (and its `Sail` dependency, lean-sail `v5`) building on 4.35.0, which is
  outside this unit and was not tested. The static counts above only bound the mechanical work
  (about 470 deprecated-name sites); the real risk is the `simp`/`omega`/`decide`-heavy proofs and the
  66 `maxHeartbeats` sites in the default targets, which cannot be assessed without a build.
