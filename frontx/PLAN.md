# frontx: working plan (helper's own notes; newest first)

## Next: structure / tuple / Option PARAMETERS and `match` on them (results are done, NOTES §10.2)

Design (not started):
- a parameter `p` of a structure type whose fields are scalars (`Prod` included; nested allowed): one variable
  per field; memo entries keyed by the projection terms `S.f p` (`Prod.fst p`); `f.Rep` conjuncts
  `σ.env v_j = rep (S.f_j p)`; `Rep`/tuple arguments keep `p` whole.
- in `trT`: a `match p with | ⟨a, b⟩ => B` (matcher on a structure) is `B (p.1) (p.2)` (no test; the kernel
  accepts it by structure eta); field accesses hit the memo. In `fun_induction` cases `p` becomes `⟨a, b⟩` and
  the projections reduce.
- at a call leaf, for a structure parameter: new component values `projNorm (π_j arg)`, compared with `π_j p`.
- `projNorm`: generalise to any projection function applied to a constructor application (`whnfR`).
- `resultComps`: generalise from `Prod` to any such structure (`getStructureFields`).
- `Option α` parameter: variables for `o.isSome` and `o.getD 0`; `match o with | none => A | some v => B v` is the
  test `o.isSome = true` with `v := o.getD 0`; `frontx_path` decides it after `fun_induction` substituted `o`.
- enum-like inductives (all constructors nullary): one tag word; needs a per-type lemma set
  (`rE x = k ↔ x = C_k`), to be generated by a small command (`frontx_enum T`).

## Done: tuple / Option results ("tagged data without allocation", results first)

Generic part (Tree.lean): `LOut.retm r rs` (`rs : List (Nat × BitVec 64)`: extra result variables and their
values), `Sim` case `∃ σ', step = some (.ret r σ') ∧ ∀ p ∈ rs, σ'.env p.1 = p.2`, `sim_retm`, `sim_retm_elim`,
`step_callQ`, `step_retQ`, `prog_okQ` (from `prog_ok`: final variables `< M`, `≠ out` are those of the tree's
final state).

Translator (recursion / non-recursive path of `compileCmd` only, not loops yet):
- result type `α × β` (right-nested) or `Option α` with scalar components: component functions `π_j`
  (`Prod.fst/snd` chains; `Option.isSome` and `fun o => o.getD 0`), `ctx.rty` = type of component 0, extra result
  variables `rv_j` allocated right after the parameters;
- at a `ret` leaf with Lean value `e` (must be a constructor application `(a, b)`, `some v`, `none`):
  `e_j := π_j e` normalised; component 0 is the `ret` expression; for `j ≥ 1` emit `let_ rv_j := e_j` items (not in
  memo/temps); outcome `LOut.retm (rep e_0) [(rv_j, rep e_j)]`, proof `sim_retm` with one `oblig` for the
  `∀ p ∈ [...]` fact;
- `f.runs : … → ∃ σ', Runs tree σ (rep (π_0 (f xs))) σ' ∧ ∀ p ∈ [(rv_j, rep (π_j (f xs)))], σ'.env p.1 = p.2`
  (tactic: `step_callQ` + `frontx_ih` / `sim_retm_elim` + `step_retQ`), `f.exec` by `prog_okQ`.
- then: tuple/Option *parameters* (one variable per component; `match p with | (a, b)`, `match o with | none | some v`
  as tests on the tag variable), structures of scalars the same way, enum-like inductives as a tag word.
